## Automatic detection and duplicate-worker prevention

Every ticket with durable `create_microticket` projection provenance is Hermes-owned for implementation. Such tickets are excluded from `claim_next_scheduler_implementation()` and from dry-run Local First implementation selection, even after the generated card has been acknowledged.

The registered one-shot scheduler and daemon poll acknowledged generated tickets for Hermes execution snapshots before the Local First implementation slot. Active/non-handoff runs are skipped. A blocked handoff with an unreconciled sentinel run is automatically reconciled. Already-reconciled runs are skipped rather than replayed as fresh work. `repairing` tickets remain Hermes-owned and can reconcile a second blocked worker run into attempt 2.

## Durable provenance handoff

The reconciler accepts generated-task board identity from acknowledged projection provenance, not only imported `tickets.external_id`.

Before creating an attempt it verifies:

1. exact Hermes task → Local First ticket identity;
2. non-final Hermes task state;
3. exact blocked sentinel for automatic handoff;
4. worktree is a Git toplevel attached to the configured canonical repository's common Git directory;
5. worker `HEAD` descends from the authoritative tranche execution base;
6. exact base-relative binary diff hash;
7. no immutable reconciliation conflict.

The first dispatcher-owned ticket in a tranche initializes/reads the tranche integration anchor through the same restart-safe `resolve_execution_base()` CAS primitive used by Local First-owned attempts.

One atomic ledger transaction creates/reuses:

- one attempt;
- one immutable `hermes_execution_reconciliations` row;
- one `model_stage_artifacts(stage='implementation', adapter='hermes-dispatch')` row;
- transition into `implementing` for a new/repair attempt.

No implementation `model_invocations` row is created.

## Restart/recovery exercised during the live proof

The real run exposed two pre-side-effect compatibility errors while new external-worktree boundaries were being integrated:

1. Git integration initially rejected the Hermes worktree because it was outside the Local First configured worktree root.
2. Tranche checkpoint initially found the Hermes worker worktree already removed after final completion.

Both failures occurred behind durable scheduler claims. After the production fixes, the same claims were replayed through normal expired-claim reconciliation (using a controlled scheduler clock just past the recorded lease expiry rather than editing claim rows). Git intent/commit safeguards prevented duplicate mutation, and the final run converged to one accepted commit/checkpoint.
