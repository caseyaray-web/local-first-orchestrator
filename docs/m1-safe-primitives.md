# M1: pure contracts and safe primitives (isolated source)

**Status:** M1 source work in `m1-safe-primitives`, based on M0 `f249699`. This is not a loaded replacement plugin, a migrated legacy runtime, a native board adapter, or authorization for a real board or model dispatch. M2 must wire the new boundaries before any recovery behavior can be claimed.

## Extracted contracts

- `local_first_orchestrator/m1_contracts.py` is an independent, versioned ticket/plan/review domain seam with no ledger, controller, host database, or model imports. `local_first_orchestrator/__init__.py` now resolves old public exports lazily so importing the pure seam does not load the old ledger. Legacy `ticket.py`, `decomposition.py`, and `review.py` remain intact for the still-running legacy call graph; M6 removes or ports them only after replacement tests exist. This is a deliberate transitional path adjustment to the final file inventory, not a second ticket lifecycle.
- New ticket contracts require explicit, finite file/line/attempt, context-token, and verification time/output budgets rather than inherited policy defaults; canonical hashes include every ticket field. Path and command declarations are immutable, normalized and bounded. The independent caller must supply the trusted verification-command allowlist; declaring a command in a ticket does not authorize it.
- Plan validation requires an external expected-criteria set. It rejects duplicate ticket/tranche IDs and tranche ordinals, missing/unknown or uncovered criteria, bad references, cycles and dependencies on later tranches. Plan hashes include full ticket payloads.
- Review normalization binds ticket contract hash and exact candidate Git SHA. A pass requires evidence for every criterion and no blockers; repair requires explicit blocking findings matching failed criteria; escalation needs an actionable reason. The result cannot be promoted to approval by a lane change.

## Git and validation

- `GitWorktreeAdapter.freeze_candidate` reads a clean, same-repository worktree against an expected base/head and records its immutable tree identity without moving refs or deleting work. `advance_integration_head` rejects a commit not descended from the expected head before its CAS update. Legacy `teardown` no longer forces removal and refuses dirty work; relevant fixture tests now assert preservation. The canonical checkout and user work are not reset.
- `DeterministicValidator.validate_strict` requires independently supplied trusted commands **and maximum timeout/output limits**. The verification runner drains stdout and stderr in fixed-size chunks, retains at most the declared output bytes per stream, and marks overflow truncated; it no longer accumulates all process output before truncation. Validation artifacts must resolve outside the candidate worktree. It compares candidate HEAD, tracked diff and file contents, and untracked **including ignored** paths/contents before and after verification; oversized Git inspection output fails closed instead of silently truncating evidence. A changed candidate fails closed while preserving the work. Existing timeout process-group cleanup, output/env bounds, scope checks and hardened Git reads remain exercised. The legacy `validate` entry remains for old tests/runtime and **still treats ticket commands as its allowlist**; M2 must use the strict entry, not call the legacy method directly.
- An old fixture expected a zero-test `unittest` command to pass. Its new-test-file scenario now creates a real test and uses discover mode, preserving line-count and staged/untracked coverage.
