# M1: pure contracts and safe primitives (isolated source)

**Status:** M1 source work in `m1-safe-primitives`, based on M0 `f249699`. This is not a loaded replacement plugin, a migrated legacy runtime, a native board adapter, or authorization for a real board or model dispatch. M2 must wire the new boundaries before any recovery behavior can be claimed.

## Extracted contracts

- `local_first_orchestrator/m1_contracts.py` is an independent, versioned ticket/plan/review domain seam with no ledger, controller, host database, or model imports. `local_first_orchestrator/__init__.py` now resolves old public exports lazily so importing the pure seam does not load the old ledger. Legacy `ticket.py`, `decomposition.py`, and `review.py` remain intact for the still-running legacy call graph; M6 removes or ports them only after replacement tests exist. This is a deliberate transitional path adjustment to the final file inventory, not a second ticket lifecycle.
- New ticket contracts require explicit, finite file/line/attempt, context-token, and verification time/output budgets rather than inherited policy defaults; canonical hashes include every ticket field. Non-goals and dependencies must be immutable strings, and nested verification/patch budgets must be exact frozen contract records, so a mutable lookalike cannot change a frozen ticket's hash. Verification declarations reject duplicates and cap commands (32), argv members (32 per command), each argument (256 characters), and total UTF-8 argv (4096 bytes). Path and command declarations are immutable, normalized and bounded. The independent caller must supply the trusted verification-command allowlist; declaring a command in a ticket does not authorize it.
- Plan validation requires an external expected-criteria set and independently trusted plan-level tranche/ticket limits (hard ceilings: 128 tranches and 2048 tickets). It rejects over-limit plans before graph traversal, and detects cycles iteratively without Python recursion. Dependencies and criterion-coverage lists are capped at 2048 references apiece, with aggregate limits of 16384 per category and at most 16384 criterion keys. It also rejects duplicate ticket/tranche IDs and tranche ordinals, missing/unknown or uncovered criteria, bad references, and dependencies on later tranches. Plan hashes include full ticket payloads.
- Review normalization binds ticket contract hash and exact candidate Git SHA. A pass requires evidence for every criterion and no blockers; repair requires explicit blocking findings matching failed criteria; escalation needs an actionable reason. The result cannot be promoted to approval by a lane change.

## Git and validation

- `GitWorktreeAdapter.create_attempt` validates ticket IDs as single safe path/ref components and checks resolved containment before making directories. Its `diff_hash` streams a binary diff with a 16 MB output cap instead of buffering it in Python. `freeze_candidate` reads a clean, same-repository worktree against an expected base/head and records its immutable tree identity without moving refs or deleting work. Ignored files prevent freezing because they are not in that tree identity; useful ignored work remains untouched. `advance_integration_head` rejects a commit not descended from the expected head before its CAS update. Legacy `teardown` no longer forces removal and refuses dirty work; relevant fixture tests now assert preservation. The canonical checkout and user work are not reset.
- `DeterministicValidator.validate_strict` requires independently supplied trusted commands and maximum timeout/output limits; it enforces a trusted aggregate verification deadline (300-second default, hard ceiling 3600), while the legacy ticket bridge shares the new argv hard caps. Snapshot file/aggregate byte limits are independently configurable with hard ceilings (defaults 8 MiB/64 MiB). The verification runner drains stdout and stderr in fixed-size chunks, retains at most the declared output bytes per stream, and marks overflow truncated. Validation artifacts must resolve outside the candidate worktree. Strict identity compares candidate HEAD, bounded Git raw path/mode metadata, and streamed file-content hashes before and after verification, without buffering a large binary diff. Ignored paths fail closed without being erased, because they cannot be frozen into Git tree evidence. Oversized Git inspection output is capped while streaming and fails closed. A changed candidate fails closed without publishing passing evidence. Successful and failed stable results write candidate-SHA/content-identity-bound evidence to new exclusive files; previous evidence is never overwritten. Existing timeout process-group cleanup, output/env bounds, scope checks and hardened Git reads remain exercised. The legacy `validate` entry remains for old tests/runtime and **still treats ticket commands as its allowlist**; M2 must use the strict entry, not call the legacy method directly.
- Legacy failed-attempt reconciliation accepts both historical deterministic artifact names and new exclusive names only inside the bound implementation artifact directory. It verifies the ledger-recorded SHA-256 and structured failure, and for new artifacts also checks candidate SHA and worktree binding. Historical records remain readable without replacing or deleting them.
- An old fixture expected a zero-test `unittest` command to pass. Its new-test-file scenario now creates a real test and uses discover mode, preserving line-count and staged/untracked coverage.
